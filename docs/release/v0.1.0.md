# StateNest v0.1.0

First public release.

## What StateNest is

A local-first control plane for your own work. It remembers your projects, where
each one lives on each machine, which servers they deploy to, what you finished,
what is blocked, and what you meant to do next — and it hands that context to
your coding agent at the start of a session.

Everything is plain YAML and Markdown in `~/.statenest`. Nothing is uploaded.
There is no account.

## Why it exists

You have forty projects and you cannot remember where you stopped in any of
them. Which repo was that? Where did I clone it on this laptop? Which VPS runs
it? What did I decide, and why?

Git history does not answer those questions, and neither does an AI chat log. A
chat log remembers what was *said*; StateNest remembers what is *true* about
your machines and repositories right now — most of it re-derived by scanning
rather than asserted by a model.

Nothing else joins *project ↔ path ↔ machine ↔ server ↔ progress*. Every tool in
the space owns one of those columns.

## Main features

- **Project discovery** — scan your directories once; StateNest finds git
  repositories, prunes aggressively, and handles symlink cycles, worktrees and
  submodules.
- **Resume** — `statenest resume <project>` gives you the summary of the last
  session, the blockers, the next actions, the branch and how many files are
  uncommitted.
- **Checkpoints** — immutable, append-only, one Markdown file each. Written by
  you or by your coding agent at the end of a session.
- **Machines** — one project, many computers. Identity comes from a hash of the
  git remote, so the same repository is one project everywhere.
- **Remotes and deployments** — which server a project runs on, at which path,
  under which service. Addresses only, never credentials.
- **Claude Code integration** — a short brief injected at session start,
  checkpoints written at session end and around compaction, seven skills and ten
  MCP tools. Adds roughly 90 ms to session start and never invokes a model.
- **Local-first** — plain files you can read, edit, grep and back up. It works
  offline, forever.
- **Optional git sync** — mirror one profile to a private repository you own.
  Off by default; it refuses to run if its secret scanner finds anything.
- **Privacy** — never stores source code, `.env` contents, keys, tokens or raw
  AI transcripts. Everything written is scanned for credentials, and everything
  read is scanned again, so a secret stored before a pattern existed still
  cannot reach your agent's context. `statenest privacy audit` checks for
  yourself.

## Installation

```bash
npm install -g statenest
statenest init
```

Requires Node.js 22.12 or newer. Works on macOS, Linux, Windows and WSL.

`statenest init` tells you exactly what it stores before it writes anything.

## Claude Code

```bash
statenest integrate claude
```

Gives you `/statenest:resume`, `/statenest:checkpoint`, `/statenest:where` and
the MCP tools Claude uses on its own when you ask what you were doing yesterday.

## Known limitations

- Secret detection is a safety net with documented limits, not a guarantee: it
  matches known credential shapes.
- Search is lexical — it finds words you actually wrote, not synonyms.
- Git is optional but nearly essential; without it, branch and
  uncommitted-change information cannot be read.
- One repository is one project. A monorepo is one project, not one per package.
- A project with no git remote gets a random identity, so the same directory
  cloned to a second machine registers as two projects until a shared remote
  exists.
- Sync conflicts are surfaced, never auto-merged.
- The on-disk format may change before 1.0.0. Migrations are applied on read and
  back up before they write.
- Claude Code is the only coding-agent integration in this release.
- This version was published by hand, so it carries no provenance attestation.
  Every release after it is published from GitHub Actions with one.

