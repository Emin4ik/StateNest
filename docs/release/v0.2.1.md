# StateNest v0.2.1

A patch release. Three fixes found while verifying v0.2.0 against real machines,
and nothing else changes: the workflow is the same, the on-disk format is the
same, and everything that was automatic still is.

```bash
npm install -g statenest@latest
statenest integrate claude
```

Run `statenest integrate claude` after upgrading — Claude Code installs a _copy_
of the plugin, so a new npm version does not reach it on its own. `statenest
doctor` reports which version it is actually running.

## A new machine appears immediately

Set StateNest up on a second computer, open your agent in a clone of a project
you already have, and that machine now shows up in `statenest where` straight
away.

Before, it appeared only from the **second** session. The first sync on a
joining machine adopts the remote history and lays the remote files over the
top — correct for shared state, since the remote is authoritative about what the
projects are. But it was also overwriting the record that session had just
written, and with it the one thing this machine had uniquely just learned: that
the project lives _here_ too.

Adoption now carries this machine's own locations across, and nothing else. The
remote stays authoritative about every other field of every record. Locations
are keyed by machine and path, so they cannot conflict — and the restored
location is pushed by the same sync, so your other machines learn about the new
one without anybody running anything.

Nothing else about a join changed: same project identity, no duplicates, and
your checkpoints, tasks and decisions arrive exactly as before.

## Compaction summaries are filed correctly

`Next:` and `Blocked:` bullets from a Claude Code compaction summary could end up
under **Recently completed**.

The condenser took its category from the last heading it had seen and applied it
to every bullet underneath. A summary written as a flat list of self-labelled
bullets — which Claude Code often produces — therefore put everything in the
first bucket. The result was worse than filing nothing: a resume brief could
claim you had finished the very thing that was blocking you.

A bullet that names its own category is now believed over the heading above it:

```
- Implemented cost-based allocation          -> Recently completed
- Next: re-run the winter fixtures           -> Next
- Blocked: waiting on the upstream tide feed -> Open blockers
- Decided: weight by vessel size             -> Decisions
```

Deliberately narrow. It acts only on a short, recognised label followed by a
colon, so ordinary prose is left exactly where it was written —
`- Refactor: split the allocator` is still completed work. Nothing is inferred
from a sentence, and a summary with no structure at all is kept as it is.

A related fix: a `## Blockers` heading now works. The pattern matched only the
singular, so the plural classified as nothing and its bullets stayed in whatever
bucket came before.

## Conflicts name the record

When two machines change the same thing, the first notice said:

```
prj_57dh4nhah58x — current state
```

It now says:

```
harbour — current state
```

which is the wording `statenest sync repair` already used. Two projects sharing
a display name are qualified by repository path, so you can tell which is which.
A name that genuinely cannot be resolved still falls back to the id — unhelpful,
never wrong.

Conflict handling itself is unchanged: both versions are kept, your local data
stays usable, and nothing is ever merged for you.

## No change to the zero-touch workflow

Everything that happened by itself in v0.2.0 still does, in the same way:

```bash
cd my-project
claude
```

Projects register themselves, context is restored, checkpoints come from
compaction, sync runs in the background. Nothing in this release adds a step,
removes one, or changes what is stored.

## Also in this release

Repository and documentation polish, worth having but not a feature:

- [`AGENTS.md`](../../AGENTS.md) for coding agents working on StateNest, and
  [`llms.txt`](../../llms.txt) as a curated entry point for agents reading the
  repository.
- [Compatibility](../compatibility.md), separating what is tested from what is
  supported from what is untested, and [project status](../project-status.md),

- A README that leads with what StateNest is rather than with its commands.
- `npm run demo:zero-touch`, a reproducible two-machine demonstration driving the
  real hooks and the real background sync.
- An architecture test enforcing the dependency direction the documentation had
  been claiming without anything checking it.

## Upgrading

Your `~/.statenest` is unchanged — same on-disk format as 0.2.0, no migration,
nothing destructive. `statenest setup` remains safe to re-run.

## Security and privacy

Unchanged. No source code stored, no raw Claude Code transcripts stored, no
account or service, credential scanning before anything leaves the machine, and
source repositories never written to. See
[security-model.md](../security-model.md) for the threat model and the documented
limits of secret detection.
